- 日期：2026-08-03
- 状态：已与用户逐条确认需求与技术选型，待用户审阅本文档后进入实施规划
- 技术栈：Tauri v2 + Rust（后端图像管线）+ React 18 + TypeScript + Vite（前端）

---

## 1. 背景与目标

用户使用 3ds Max 导出多个**同尺寸、带透明通道（alpha）的漫反射贴图**（PNG），每张贴图只在画面部分区域有像素信息，其余为全透明。需要将这些贴图**层层重叠合成**为一张同尺寸的 PNG：透明区域透出下层像素，最终完整利用整张图片区域。

典型规模：贴图数量几百张，单张分辨率 2K / 4K / 8K，文件体积较大，**效率是核心关注点**。

### 关键定义（与用户确认）

- **合并方式 = 重叠合成**，不是网格拼合/图集打包。输出图像分辨率与单张输入完全相同。
- 图层顺序：**列表顶部 = 最上层**（Photoshop 习惯），合成时从底部逐层向上做 alpha 混合。
- 混合模式：仅标准 source-over（上层不透明像素覆盖下层；上层透明处露出下层），不做其他混合模式。

## 2. 功能需求

### 2.1 导入

| 方式 | 说明 |
|---|---|
| 拖拽导入 | 将图片文件或文件夹直接拖入窗口 |
| 文件多选对话框 | 选择多个 PNG 文件 |
| 文件夹批量导入 | 选择文件夹，自动扫描其中所有 PNG 文件（可含子目录，实施时确定） |

导入行为：
- 立即异步解析每个文件的 PNG 元信息（宽/高/是否有 alpha），生成小尺寸缩略图（约 128px），追加到图层列表。
- 非 PNG / 损坏文件：标记为失败项（列表中以提示样式显示），不中断整个批次。
- 尺寸不一致：显示警告（提示用户核对；合成按统一尺寸处理）。
- 全透明图层或重复文件：正常导入，不做特殊拦截（实施时可按提示优化）。

### 2.2 图层操作

| 操作 | 说明 |
|---|---|
| 拖拽排序 | 调整层叠顺序（顶部=最上层） |
| 可见性开关 | 每个图层眼睛图标，临时隐藏/显示该层，隐藏层不参与预览与导出 |
| 旋转 90° | 顺时针，可连续点击（0°→90°→180°→270°） |
| 水平/垂直翻转 | 两个方向独立 |
| 移除 / 替换 | 单张移除；替换 = 用新文件替换某图层（保留原顺序与变换） |
| 清空 | 一键清空全部图层 |

所有变换均记录在图层数据中，预览与导出使用同一套变换逻辑，保证所见即所得。

### 2.3 预览

- **图层列表**：左侧竖向虚拟滚动列表（几百张不卡），每项显示缩略图、文件名、尺寸、操作按钮。
- **大画布**：右侧实时预览重叠合成结果，棋盘格背景展示透明区域。
- **缩放/平移**：画布支持缩放（如 10%–800%）与平移，"适应窗口"一键复位。
- **联动高亮（单独查看）**：点击某图层 → 画布仅显示该图层像素，左上角显示"仅查看：xxx"提示；点击画布空白处返回全部预览。此时其余图层临时隐藏，不影响图层可见性设置本身。
- 预览分辨率独立于导出分辨率（默认按画布尺寸自适应，可缩放），变更即时刷新。

### 2.4 导出

- 输出尺寸 = 输入单张尺寸；输出为单张 PNG（带 alpha）。
- **位深**：8bit / 16bit 每通道可选（16bit 输出文件更大、耗时更长）。
- **压缩级别**：快速 / 均衡 / 最大 三档（映射到编码参数，实施时确定具体值）。
- **命名**：导出对话框中自定义文件名与保存目录；同名文件存在时询问覆盖或自动追加序号。
- 导出过程：后台执行（不阻塞界面），实时进度条，可随时取消；完成后可选择打开所在文件夹。
- 位深换算规则：输入 8bit 输出 16bit 时按 `<<8` 放大；输入 16bit 输出 8bit 时按 `>>8` 缩小（输入以 8bit 为主）。

### 2.5 状态栏

显示：图层总数、输出尺寸（=单张尺寸）、预估导出内存/体积、预览分辨率、当前状态（导入中/预览刷新中/导出进度/就绪）。

### 2.6 关于对话框

「ⓘ 关于」按钮与位深/压缩等设置项**同一行、同一按钮风格**（工具栏设置区），点击弹出模态框，内容：

- 工具名称：贴图合并工具
- 版本：v1.0.0（随发布更新）
- 作者：@月石MoonStone
- 联系方式：ryantxq@sina.com
- 使用说明（简要操作步骤，见下文）
- 关闭按钮；点击遮罩或 ✕ 也可关闭

使用说明内容（展示于弹窗内）：

1. 将 3ds Max 导出的同尺寸带透明通道 PNG 拖入窗口，或通过「导入/选择文件夹」批量添加；
2. 在左侧图层列表调整顺序（顶部=最上层）、旋转/翻转，可用眼睛图标临时隐藏图层；
3. 在右侧画布实时预览重叠合成效果，点击图层可单独查看该层像素；
4. 设置位深与压缩级别，点击「导出 PNG」选择保存位置完成导出。

### 2.7 亮/暗主题

- 工具栏右侧提供主题切换按钮（☀/☾），支持 **亮色 / 暗色** 两套主题全局切换。
- 默认跟随系统（prefers-color-scheme），手动切换后记录到 localStorage（仅界面偏好，不属工程文件）。
- 所有界面元素均跟随主题：工具栏、图层列表、画布棋盘格背景（暗色用暗色棋盘格）、对话框（含关于/导出）、状态栏、滚动条等，统一通过 CSS 设计变量（design tokens）实现。
- 预览画布内容（贴图本身）不随主题变化，仅棋盘格背景等 UI 元素变化。

## 4. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | Tauri v2 | 安装包小（~10MB）、内存占用低、前端可做现代界面 |
| 图像管线 | Rust（多线程） | 几百张 2K-8K 解码/合成/编码的性能与内存可控 |
| 前端 | React 18 + TypeScript + Vite | 组件化状态管理、生态成熟（虚拟列表/拖拽排序） |
| 并行 | rayon（实施时按需） | 解码/编码多线程 |
| 对话框 | tauri-plugin-dialog | 文件多选、文件夹选择、保存对话框 |

本机环境：已有 Node v24.12.0、Git、MSVC Build Tools 18；需安装 Rust 工具链（rustup）后方可开发。

## 5. 架构与组件

```
┌────────────────────────────────────────────────┐
│ Web 前端（React + TS + Vite，WebView2）         │
│  Toolbar / LayerList / PreviewCanvas /          │
│  ExportDialog / StatusBar                       │
└───────────────────┬────────────────────────────┘
          Tauri IPC（invoke 命令 + 事件）
┌───────────────────┴────────────────────────────┐
│ Rust 核心（tauri 后端）                         │
│  ├ import: 解析 PNG 元信息 + 生成缩略图(异步)    │
│  ├ preview: 按图层状态合成低分辨率预览图         │
│  ├ composite: 全分辨率合成（source-over）        │
│  └ export: PNG 编码（位深/压缩参数化）+ 进度事件  │
└────────────────────────────────────────────────┘
```

### 5.1 Rust 侧模块划分

- `model`：`Layer`（id、路径、名称、宽高、变换、可见性）、`ProjectState`（图层有序列表 + 导出设置，仅内存态）
- `import`：文件扫描、PNG 元信息解析、缩略图生成（后台线程池）
- `preview`：按图层顺序/变换/可见性合成指定分辨率的预览图，输出 RGBA 数据或 PNG 字节
- `composite`：全分辨率合成核心（source-over 混合、旋转/翻转采样），预览与导出共用
- `export`：位深与压缩参数化编码、进度上报、取消标志

### 5.2 前端组件

- `Toolbar`：导入（拖入提示 + 多选 + 文件夹）、位深下拉、压缩下拉、导出按钮
- `LayerList`：虚拟滚动列表、拖拽排序、眼睛/旋转/翻转/移除、选中态；底部"清空"
- `PreviewCanvas`：棋盘格背景、缩放/平移/适应、单独查看模式与返回
- `ExportDialog`：文件名、目录、位深、压缩、进度条、取消
- `AboutDialog`：版本/作者/联系方式/使用说明展示（纯前端，无 IPC）
- `ThemeToggle`：亮/暗主题切换按钮，CSS 设计变量驱动，偏好存 localStorage
- `StatusBar`：状态信息展示

### 5.3 IPC 接口（示意）

- `import_files(paths) -> Vec<LayerMeta>` / `import_folder(path) -> Vec<LayerMeta>`：导入并返回元信息（含缩略图数据）
- `build_preview(snapshot, width) -> PreviewImage`：按当前图层快照合成预览图（前端把顺序/变换/可见性作为快照传入，保证一致性）
- `export(snapshot, options, save_path)`：全分辨率合成并写出 PNG，过程中发出 `export_progress` / `export_done` / `export_failed` 事件；支持取消（`cancel_export`）

## 6. 数据流

1. **导入**：前端收集路径 → `import_files` → Rust 异步解码元信息 + 生成缩略图 → 返回图层元信息 → 前端追加到列表并触发预览刷新。
2. **预览**：任何变更（增删/排序/旋转/翻转/可见性）→ 前端 300ms 防抖 → 提交图层快照 → Rust 后台合成预览图 → 前端 canvas 绘制。
3. **导出**：前端提交快照与导出设置 → Rust 逐层解码并 source-over 合成到输出缓冲 → 编码 PNG 写盘 → 进度事件；取消时中止并删除不完整文件。

合成顺序：从图层列表尾部（最底层）开始逐层向上到头部（最上层）；隐藏层跳过。

## 7. 性能设计

| 关注点 | 方案 |
|---|---|
| 几百张导入慢 | 后台线程池并行解析元信息与生成缩略图；缩略图只生成一次 |
| 预览卡顿 | 预览始终用低分辨率合成（按画布尺寸），变更防抖 300ms，合成在后台线程执行 |
| 全分辨率合成内存 | 输出缓冲常驻一份（2K≈16MB / 4K≈64MB / 8K≈256MB / 16K≈1GB），逐层解码→合成→释放，峰值 = 输出缓冲 + 单张解码缓冲 |
| 导出慢 | PNG 编码启用多线程（rayon）；压缩级别可调（快速档显著提速）；进度实时可见 |
| 大图显示流畅 | 前端仅传输/绘制预览分辨率图像，canvas 缩放渲染 |
| 数据一致性 | 预览与导出共用同一套合成核心（composite），杜绝两套逻辑漂移 |

预估内存提示：状态栏实时显示 宽×高×字节数（按位深），超过阈值（如 2GB）时导出前弹窗提醒。

## 9. 错误处理

- 非 PNG / 损坏文件：导入时标记失败项，不中断批次
- 尺寸不一致：警告提示
- 导出失败（磁盘满/路径无权限/文件被占用）：明确错误提示，保留可用的已写文件或清理不完整文件
- 导出中途取消：删除不完整文件
- 解码失败的单层：导出时跳过并汇总报告"N 层解码失败被跳过"

## 10. 测试

### Rust 单元测试
- 合成核心：多图层 source-over 混合正确性（含旋转/翻转/可见性组合），与手算或参考图像对比
- 位深换算：8→16 放大、16→8 缩小的数值正确
- PNG 编码往返：导出后重新解码，像素与预期一致（8bit 与 16bit 各测）
- 缩略图管线：尺寸/格式正确
- 网格无关：确认输出尺寸恒等于输入尺寸

### 手工 QA
- 百张级（300 张 2K）导入流畅度与内存表现
- 预览交互：拖拽排序、旋转/翻转、可见性、单独查看、缩放平移
- 关于弹窗：版本/作者/联系方式/使用说明显示正确，打开与关闭正常
- 亮/暗主题：切换后各界面元素（列表/画布棋盘格/对话框/状态栏）随主题正确变化，偏好记忆生效
- 8K 单层与 300 层混合场景导出耗时/内存实测；取消导出
- 与 3ds Max 导出素材联测：同象限多贴图重叠合成结果符合预期
